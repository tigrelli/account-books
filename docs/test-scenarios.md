### 사용자 가이드 참고 — 품목 병합 동작 설명 (2026-07-04 PM 문의 대응, 같은 날 동작 수정 반영)

> 이 절은 나중에 사용자 가이드를 쓸 때 그대로 옮겨 쓸 수 있도록 사용자 관점 언어로 정리한 것 — PM 문의 "병합했는데 지출 보기엔 여전히 옛 이름으로 보인다. 병합은 언제 쓰이는 거냐"에서 시작해, "병합한 의도는 앞으로도 같은 이름으로 입력하면 계속 하나로 잡히길 원하는 것"이라는 PM 확인에 따라 동작을 수정함.

- **병합은 "표시 문구"를 바꾸지 않습니다.** 지출을 입력할 때 실제로 타이핑한 텍스트(예: "깐 양파")는 영수증처럼 그대로 남습니다 — 지출 보기/수정 화면에 계속 그 문구로 보이는 게 정상입니다.
- **병합이 하는 일은 "이 지출을 통계에서 어떤 품목으로 계산할지"를 다시 연결하는 것입니다.** 병합하는 순간 과거 지출들은 즉시 새 품목("양파") 기준으로 재연결됩니다.
- **병합하는 목적은 결국 품목별 통계(Top10 등)를 정확히 보기 위함입니다.** "깐 양파"와 "양파"를 따로 세면 통계가 갈라지니, 병합해서 하나로 합쳐 보려는 것 — 즉 병합은 "지금 당장의 화면 표시 변경"이 아니라 "나중에 통계를 정확히 합산하기 위한 사전 작업"입니다.
- **병합 이후 새 지출을 입력할 때(2026-07-04 수정 후)**: "깐 양파"라고 타이핑하면 자동완성에 "양파"가 뜨는데, **그 제안을 클릭해서 선택하지 않고 그냥 타이핑만 하고 넘어가도** 서버에서 이름/별칭 일치 + 병합 체인을 따라가 자동으로 "양파"로 연결됩니다. 즉 병합해두면 그 이후로는 "깐 양파"든 "양파"든 어떻게 입력해도 항상 하나의 품목으로 잡힙니다.
  - **수정 전 알려진 문제**: 원래는 자동완성 제안을 직접 클릭해야만 병합된 품목으로 연결되고, 그냥 타이핑만 하면 이름이 정확히 일치하는 옛 품목("깐 양파", 병합되어 화면엔 안 보이지만 데이터는 남아있음)을 그대로 재사용해 "한 다리 건너" 연결되는 문제가 있었음 — `apps/main/web/app/(app)/expenses/actions.ts`의 `resolveItemId`가 이름 완전일치만 검사하고 별칭·병합 체인을 확인하지 않았기 때문. 사용자 실제 데이터로 재현 후(`transaction_detail`/`item` 조인 쿼리) 수정 완료 — 회원가입→상세입력 2건("양파"/"깐 양파" 각각 신규 생성)→병합→병합 후 "깐 양파" 재입력(자동완성 미선택) 전체 흐름을 재현해, 새 항목이 옛 "깐 양파" 품목이 아니라 "양파"에 직접 연결되는 것을 DB 조회로 확인.
- (개발 메모) 품목별 통계 화면(F-3-1-3, Top10) 자체는 아직 미착수 — 다만 위 수정으로 병합 시점 이후의 신규 지출은 항상 최종 대표 품목 id로 즉시 연결되므로, 이 화면이 만들어지면 단순히 `item_id` 기준으로 집계해도 정확함(기존에 유일하게 남아있던 위험은 병합 전에 이미 저장된 과거 데이터인데, 그건 병합 시점에 이미 일괄 재배정됨). `lib/item-merge.ts`의 `resolveCanonicalItemId`/`groupByCanonicalItem`은 그래도 방어적으로 유지 — 혹시 모를 재배정 누락(멀티 스테이트먼트 트랜잭션 미지원 등)에 대비.
- (개발 메모) 이 수정은 서버 액션(`resolveItemId`)의 DB 조회 로직 변경이라 스키마/UI 자동화 테스트로 커버하기 애매해 자동 회귀 테스트는 아직 없음 — 위 시나리오를 Playwright로 수동 재현 + DB 직접 조회로 검증. 필요하면 추후 별도 E2E/통합 테스트로 승격 검토.
