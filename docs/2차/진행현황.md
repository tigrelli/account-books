  > **최종 검증(로컬, 실제 사진)**: 회원가입 테스트 계정 + 실제 관리비 고지서 사진으로 "충돌 없음" 경로 정상 확인("2026-01 청구월 · 총액 165,600원" 표시). 케이스 A/B(팝업 분기)는 코드는 스펙대로 구현하고 기존 검증된 Dialog 컴포넌트를 그대로 재사용했지만, 로컬 DB의 `service_role`이 `payment_method`/`category` 테이블에 대한 GRANT 자체가 없어(1차부터 있던 기존 갭 — `synonym_dictionary` 외 테이블엔 service_role GRANT가 애초에 없었음, 오늘 처음 service_role로 직접 시드하려다 발견) 자동화된 시드 데이터로 E2E 재현은 못 했음. 또한 케이스 A(수동 등록 존재)는 애초에 "수동 지출 입력 시 UTILITY_BILL_RECORD(source=MANUAL) 생성" 로직이 아직 어디에도 구현되어 있지 않아(F-2-4-3은 "변경 없음"으로 명시) 지금 시점엔 실제로 발생할 수 없는 케이스이기도 함 — 실사용 가능한 시점(F-2-1-3 완료 후 케이스 B, F-2-4-3 완료 후 케이스 A)에 재검증 권장. typecheck/lint 통과.
