## 1. 명세서 업로드 화면 (`/utility-bills/upload`, F-1-2-1)

### 1-1. 레이아웃

- 상단: 화면 타이틀 + "통계 보기" 버튼(우측 상단, `--color-action` 텍스트 버튼)
- 중앙: 업로드 영역(드래그앤드롭 박스 + "사진 촬영/파일 선택" 버튼, 모바일에서는 카메라 촬영이 기본 경로)
- 하단: 최근 등록 내역 요약(최근 3개월 등록 여부를 작은 리스트로 — "3월: 업로드됨 / 2월: 업로드됨 / 1월: 미등록" 형태)

### 1-2. 처리 분기 로직

파일 업로드 완료 시 서버가 아래 순서로 판별합니다.

1. `UTILITY_BILL_RECORD`에서 `(user_id, period)` 조회
   - `source='MANUAL'` 존재 → **케이스 A(차단 팝업)**, 아래 절차 중단
   - `source='UPLOAD'` 존재 → **케이스 B(재업로드 확인 팝업)**
   - 없음 → 통과
2. OCR로 라벨 추출
3. 사용자의 `UTILITY_BILL_ITEM.source_labels`(활성 항목 기준)와 추출된 라벨을 비교해 매칭률 계산
   - **매칭률 ≥ 50%** → 동일 양식으로 판단, 확인 화면(1-5)으로 진행
   - **매칭률 < 50%**(지정 항목이 하나도 없는 최초 업로드 포함) → 형식변경/최초로 판단, 항목 선정 화면(§2)으로 진행

> 매칭률 50% 기준(제안값)입니다. 실제 OCR 정확도가 확인되면 화면설계 확정 전 실측 데이터로 재조정할 수 있습니다.

### 1-3. 재업로드 충돌 팝업 (레이어 팝업, confirm형)

| 케이스                 | 문구                                                                                              | 버튼                      |
| ---------------------- | ------------------------------------------------------------------------------------------------- | ------------------------- |
| A. 이미 수동 등록 존재 | "이미 등록한 {N}월 관리비 내역이 있습니다.\n관리비 내역을 삭제 후 명세서를 업로드할 수 있습니다." | 확인(닫기만, 업로드 취소) |
| B. 이미 업로드 존재    | "이미 등록된 {N}월 명세가 있습니다.\n재업로드 할 경우 기존 데이터는 삭제됩니다."                  | 취소 / 재업로드 확정      |

케이스 B에서 "재업로드 확정" 선택 시 기존 `UTILITY_BILL_RECORD`(및 하위 `UTILITY_BILL_ITEM_VALUE`, 연결된 `TRANSACTION`)를 삭제하고 1-2의 3번부터 다시 진행합니다.

### 1-4. 처리 중 상태 표시

데이터 구조 설계 §7 결정대로 별도 로딩 레이어 팝업 없이 처리합니다. 업로드 버튼 클릭 후 버튼을 비활성화하고 인라인 스피너("처리 중...")만 표시합니다. Vercel/Supabase 무료 함수 시간제한(150~300초)에 근접하는 사례가 실측에서 확인되면 이 화면의 상태 표시 방식(동기 대기 vs 비동기 알림)을 재검토합니다.

### 1-5. 업로드 완료 확인 화면

지정 항목별 매칭된 금액을 리스트로 보여주고("전기료 16,186원" 등), 최상단에 고지서 총액을 표시합니다. 지정 항목 합계와 총액이 다르면 이 화면에서부터 차이 금액을 안내합니다("지정 항목 합계와 총액이 {차이}원 다릅니다 — 통계에서 계속 확인할 수 있습니다"). "저장" 버튼(`--color-action`)으로 확정하면 `TRANSACTION`(`occurred_at`=청구월 말일, 데이터구조설계 §2-4 참고) + `UTILITY_BILL_RECORD` + `UTILITY_BILL_ITEM_VALUE`가 생성되고, 저장 직후 레이어 팝업으로 지출일 안내를 표시합니다(§5 공통 팝업 문구 표 참고).

## 2. 항목 선정 화면 (`/utility-bills/upload/items`, F-1-2-2)

### 2-1. 진입 조건

최초 업로드 또는 형식변경 감지 시에만 진입(1-2 참고). 별도 페이지이며 팝업이 아닙니다.

### 2-2. 구성

- 추출된 항목 리스트: 체크박스 + 항목명(OCR 원문 라벨) + 금액 + (사용량표에서 매칭되는 라벨이 있으면 "사용량 연결됨" 배지)
- 기존 지정 항목이 있던 경우(형식변경 케이스): 더 이상 추출되지 않는 기존 항목은 "이번 달에 없음 — 비활성화" 안내와 함께 별도 구획에 표시
- 하단 고정 바: "선택한 항목으로 저장" 버튼

### 2-3. 검증

최소 1개 이상 선택해야 저장 가능(0개 선택 시 버튼 비활성화 + "최소 1개 이상 선택해주세요" 안내). 저장 시 신규 `UTILITY_BILL_ITEM` 생성, 해제된 기존 항목은 `is_active=false`로 전환.

## 3. 명세서 통계 화면 (`/utility-bills/stats`, F-1-2-3)

### 3-1. 콘텐츠 우선순위 (확정)

| 우선순위         | 콘텐츠                              | 비고                                        |
| ---------------- | ----------------------------------- | ------------------------------------------- |
| 1순위(MVP 필수)  | 총액 불일치 알림 아이콘             | 있을 때만 상단 노출, 클릭 시 팝업           |
| 1순위            | 총액 추이(월별, 입력방식 무관 전체) | 라인 차트, 수동입력 달은 "수동 입력됨" 배지 |
| 1순위            | 항목별 추이                         | 업로드된 달만, 값 없는 달은 "-"             |
| 2순위            | 전월 대비 증감률 요약 카드          |                                             |
| 2순위            | 항목별 비중 도넛                    | 최근 달 기준                                |
| 3순위(후속 확장) | 최다 증가 항목 하이라이트           | "이번 달은 난방비가 올랐어요" 형태          |
| 3순위            | 사용량/단가 추이                    | `has_usage=true` 항목만 대상                |
| 3순위            | 연간 총합계, 전년 동월 비교         | 데이터 12개월 이상 누적된 후 의미 있음      |
| 3순위            | 비지정 항목 리스트(+지정 항목 승격) | `TRANSACTION.raw_payload` 조회              |

MVP는 1·2순위만 구현하고, 3순위는 `docs/백로그.md`에 후속 확장으로 기록합니다.

### 3-2. 레이아웃 순서

상단 알림 아이콘(있을 때) → 총액 추이 차트 → 전월대비 증감률 카드 → 항목별 추이 차트 → 항목별 비중 도넛 → (3순위 항목은 하단에 접이식 섹션으로, MVP에서는 숨김 처리 가능)

### 3-3. 총액 불일치 팝업

클릭 시 레이어 팝업: "지정 항목 합계({A}원)와 실제 등록 금액({B}원)이 다릅니다. 명세서에 지정하지 않은 항목이 있거나, 지출 내역에서 금액을 직접 수정하신 경우 발생할 수 있습니다."

## 4. 기존 화면 변경분

### 4-1. 지출 입력 (`/expenses/create`, F-1-1-4 유지)

변경 없음. 카테고리 "관리비/공과금" 선택 시에도 기존 금액 직접입력 폼 그대로 사용합니다.

### 4-2. 지출 내역 / 지출 수정 (F-1-1-11/12, F-1-2-5)

`UTILITY_BILL_RECORD.transaction_id`로 연결된 트랜잭션인 경우, 수정 화면 진입 시 안내 배너를 표시합니다: "이 지출은 관리비 명세서로 등록되었습니다. 금액을 수정해도 항목별 통계는 원본 그대로 유지됩니다." 목록 화면에서는 이런 트랜잭션에 작은 아이콘 배지(예: 문서 아이콘)를 붙여 구분합니다.

## 6. 디자인 토큰 적용

- 저장/업로드 등 CTA 버튼: `--color-action`
- 총액 불일치 알림 아이콘, 마이너스성 강조: `--color-paylens-accent`
- 항목별 비중 도넛: 기존 대시보드(F-5-3)와 동일한 카테고리 컬러 체계 재사용
- 금액/수치 표기: `--font-data`(JetBrains Mono)
- 카드 스타일: `--card-shadow`, `--border-radius-m`(12px) 기본값 그대로 사용

## 7. 모바일 대응

업로드 화면은 모바일에서 "사진 촬영"이 기본 동선입니다(파일 선택은 보조). 항목 선정/통계 화면은 기존 반응형 규칙(사이드바 → 좌측 슬라이드 드로어)을 그대로 따릅니다.
